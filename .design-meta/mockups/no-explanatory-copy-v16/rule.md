## 少写字，让版式说话（2026-10-23 用户定，文案第一条）

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

界面上能出现的字只有四种：**标题**（页面、区块、卡片的名字）、**数字和事实**（“42 笔”“上次对账 10月2日”）、**控件上的字**（按钮、芯片、开关、行名）、**状态**（“没分类”“已停掉”“过了 3 天还没记”）。除此之外的每一行字（副标题、说明句、口号、操作提示、步骤、安慰话、“例如：…”）默认不写。想加一行之前按顺序问，前一步能解决就停下：

1. **删掉会怎样？** 用户删掉后照样知道下一步做什么，就删。
2. **用层级说。** 位置、分组、大小、字重、对齐、颜色（amber = 要你看一眼）。同组的东西放进一张卡，比写“以下是…”清楚。
3. **用控件说。** 按钮写结果（“停掉以后的”比“只停以后的，已到期账单保留”+“确定”好）；能点就有 ›、能勾就有勾框、能滑就露一点边、不能用就是禁用态；占位里的“例如：外卖、学习”换成可点的建议芯片；需要设置的地方直接放“去设置”按钮，不写设置路径。
4. **用状态和数字说。** 圆点、进度、计数、对比、空的虚线轮廓，比一句描述快。
5. **挪到发生的那一刻。** 后果写在确认框和撤销提示条里，只在真的要发生时出现一次；第一次用到某个功能时才讲，而且用一张可关掉的卡，不常驻。
6. **以上都不行，才写一行。** 只写事实或数字，一行以内，`meta` 或 `caption`；不写理由、不写怎么运作、不写口号。

**不写的东西**（全应用一律删掉，新稿也不再出现）：

| 类型 | 例子（来自现有界面） | 换成 |
|---|---|---|
| 口号、品牌话 | 你的账本，只属于你；余白在听，也在想…；这周我对你多了解了一点；余白在这台手机上 | 删；或换成一个数字（“占 38 MB”）、一个记号（水波起伏表示在想） |
| 操作说明 | 点一笔可以改；选出要记的几笔，点一笔可以核对；正在听，停下后可以修改再发送；长按锁屏或主屏 › 添加小组件 › 余白 | 行尾 ›、勾框、听写时把文字实时写进输入框、小组件缩略图 + “添加”按钮 |
| 步骤清单 | 1. 打开快捷指令… 2. 选择付款卡… 3. … | 一个按钮直达（“添加到快捷指令”），完成后行尾变成 ✓ |
| 怎么运作、让人放心的话 | 在本机读完，没有发给云端；只存在本机内存，关掉应用就清空；密钥仅保存在本机钥匙串… | 一枚小胶囊“本机”/“云端 · 5 行”，点开才看细节；设置页里写一次就够 |
| 重复标题的副标题 | 愿意多花的 · 原则；你常花的 · 来自账本；支出 · 按类型 | 只留前半；来源用图标或分组表达 |
| 邀请、安慰、劝告 | 还没有写下，想到时再添；有了消费记录，再一起看看；问问余白：该不该买？ | 空状态只留标题 + 一个按钮 |
| 占位里的“例如”和“（可选）” | 名称，例如：微信零钱 / 招商银行卡；为什么重要（可选） | 建议芯片；可选的字段放在“更多”里或默认收起 |
| 出错时只写“请到某处做某事” | 先到智能与隐私填写密钥，开启云端智能 | 一句事实（“还没配密钥”）+ 按钮“去配置” |

**允许写的例外**：不可撤销操作的确认框写一句后果；出错写原因并给按钮；读屏的 `accessibilityLabel`/`accessibilityHint` 不受限（看不见，要写完整）；系统权限说明（Info.plist）照写。

**给实现的检查**：每个 UI 改动列出新增的可见文字。不是标题、数字、控件字、状态的，要说明上面 1–5 步为什么不行；说不出就删掉。设计稿里没有的说明句，代码里也不加。
