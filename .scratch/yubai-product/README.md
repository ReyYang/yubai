# 地图使用说明

本目录按 wayfinder 的 Local Markdown tracker 约定组织。入口是 [余白产品定义决策地图](map.md)。

产品与设计的总入口见 [设计资源与当前进度](../../.design-meta/README.md)。本目录继续承载产品事实、决策票、研究与原型；以下 tracker 约定用于推进具体票，不要求框架资料维护同时解决产品决策。

- 地图是 `map.md`；每张子票在 `issues/` 单独保存。`Parent` 指向地图，`Labels` 记录 wayfinder 标签，`Type` 记录票类型。
- `Status: open` 且 `Assignee: unassigned` 表示未领取。领取时先将状态改成 `claimed` 并填写负责推进的用户，再开始工作。
- 本地 tracker 没有原生依赖，使用 `Blocked by` 引用票号。空值表示无依赖；全部依赖票均为 `resolved` 时才解阻。
- 查询当前可推进票：扫描 `issues/`，筛选 open、unassigned 且依赖全部 resolved 的文件，按文件编号排序。地图正文不重复列出开放票。
- 解决时按本地 tracker 约定将答案追加至票末尾 `## Answer`，设 `Status: resolved`；在地图的 Decisions so far 追加标题链接与一句摘要。不把详细答案复制进地图或术语表。
- 后续讨论记录可追加于 `## Comments`；不得把候选建议默认为用户决策。
- 每轮最多解决一张非研究票。新票先创建，再设置依赖；需检查引用有效且不存在依赖环。
- `CONTEXT.md` 只记录已经澄清的领域词汇，不承载需求清单、实现细节或决策答案。

2026-10-01 用户已明确委托自主实施完整个人产品；第 13 票承载本轮采用决定与交付证据，旧逐票规划流程不限制该委托。历史票仍保留用户确认、候选与未知的区别。本轮已实现原生应用，未处理用户真实账单或发送财务数据。
