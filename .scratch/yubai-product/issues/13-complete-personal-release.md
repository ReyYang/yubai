## 当前授权与目标

用户本次明确委托 Agent 自主主导产品、联网调研竞品和 UI/组件、实现可安装且完整供个人使用的软件；不要以 MVP 或孵化中的版本交付。用户进一步确认「iPhone 优先，Mac 也能用」。本次委托覆盖可恢复的产品、视觉、技术与实现决定，替代旧讨论阶段逐票 HITL 的执行限制；不把 Agent 决定写成用户逐项确认。

## 本次采用决定（委托下制定）

以下为 1.0 阶段及 2026-10-15 的历史采用记录；其中示例入口、规则管理、本机模型、导航和维护页面已由下方 2026-10-20 的 2.0 决定替代。保留记录不表示这些功能仍在应用中。

- 一个余白产品，同一套 SwiftUI 原生界面与财务引擎，iPhone / Mac 适配，包含尚未专门验收的 iPad 构建入口；使用 Swift Charts、SF Symbols、系统文件选择和系统分享。原 HTML 草稿保留为历史候选。
- 本地优先；不创建账号、服务器或订阅。人民币金额按整数分记账。真实账本默认空白；可单独进入示例账本，示例不可混入真实数据。
- 账户以用户核对时刻的余额为锚，历史导入不重复修改当前余额。未核对、逾期、未知性质、遗漏导入均显示数据依据与影响。
- 性质独立于分类：支出、收入、内部转账、还款、借入、借出、归还借款、收回借款、退款、分摊收款、投资申购/赎回、调整、待明确。内部移动和本金不虚增日常收入支出。
- 动态资金从今天推演，期限可调；现金、信用负债、投资分别列示。已知付款和目标预留扣除；未来收入单独呈现，保守可动用金额不依赖尚未到账收入。不自动分配、不执行付款。
- 房租记录总租金、个人承担、月收季付日期和每期实收实付；既能关联账本记录，也能标记已发生付款。未收分摊不提前当可花钱，租金支出按本人实际承担口径展示。
- 文件导入支持中文账单 CSV/TSV（UTF-8/GB18030/UTF-16）和 XLSX；保留来源原件、行号与去重 ID，导入前预览、异常行可见、整批撤销；用户纠正优先于再次导入。跨来源相似项只提示，不能盲删。
- 截图使用本地文字识别生成待确认记录；金额必须由用户确认。正式账本支持搜索、筛选、批量改类、自定义分类和学习规则、交易编辑/删除/恢复。
- 资金安排、目标、周期收支、信用到期日、投资快照、收支分析、购买前判断、备份/恢复/CSV导出均在完整闭环中。
- AI 不改金额、账户或资金性质。产品主路径改为**本地优先**：规则底座 +（可选）下载的本机开源模型；Apple 系统模型仅为可选旁路，不作可用性承诺。云端增强为可选且**默认关**（接口预留，字段仍见第 01 票）。无模型时保持规则分类与有依据的资金判断。不把规则模板声称为已执行模型推理。权威方向见项目 Agent Store `docs/ai-local-first-plan.md`；实现入口为 `Intelligence*`、`ModelWeightStore`、`SettingsView`。
- 本地数据保存采用原子写入与版本化格式，每次修改保留可恢复历史；备份包含原始附件，可选密码加密。恢复前校验并保留原账本。

## 2026-10-20 · 用户批准的 2.0 导航与删减

用户本轮明确批准三个入口：现在（来信、管家、保守可动用及依据、待付款、导入）、我（消费观、心愿单、账户、导入记录、智能与隐私、备份与恢复、指南）、常驻问余白。删除旧账本、安排、洞察、分类／规则管理、手工计划／房租／16 性质编辑、判断历史、CSV 导出／模板与应用内示例；删除界面不删除旧用户数据，schema 2 继续保留旧字段。目标编辑仅供消费观使用；依据仍可打开原始记录，删除后只有撤销／完整恢复版本可恢复。

以下为 Agent 在授权内采用的实现口径：资金默认固定 90 天，底线读取 profile.floorAmount（旧版应急底线在读取时自动迁入；都未填写为 0），日常生活按近 90 天估算，旧资金偏好继续存档而不参与计算。用户随后要求兼容旧应急预留；具体迁移方式是解码 schema 1 或旧 schema 2 账本时，若 floorAmount 缺失且 preferences.emergencyReserve > 0，则迁入 floorAmount；已有底线（含 0）保持原值。Agent 选择两端底部常驻按钮承载问余白，保留部署范围；endPlan 同时处理计划和房租，开始前停用、开始后保留已到期记录并截断未来期次。完整备份界面要求至少 8 位密码，旧未加密备份仍可读取。数值与算法不作为用户逐项批准的产品规则，详见下方决策归档。

源码和指南已同步；SampleData 移入测试目标，新增五条仅 Debug simulator 可用的独立合成账本／脚本传输 UI 流程。当前无 Swift 工具链，仅静态语法和工程引用核查；尚未编译或运行测试。历史 Figma、原型、截图、分发包未同步，本票仍 in-progress。上方 1.0 采用记录作为历史保留，不作为当前入口清单。


## iCloud 账本的采用边界

用户明确要求 iPhone 和 Mac 可通过 iCloud 共享同一账本；冲突保留各版本，由用户选择，不自动合并。由于可能只有免费 Personal Team，iCloud 构建默认关闭，单行配置启用；未启用或容器不可用时维持本机存储。两端仍共用现在／我／问余白，「我」下的备份入口改为「备份与同步」。此要求取代上方历史「无自动云同步」的范围边界，不改变默认本地优先。

授权内实现选择：应用的存储位置仍默认仅本机；附件从 schema 2 的内嵌 JSON 迁为同目录不可变 UUID 文件，完整加密备份包含附件字节。恢复历史（最近 20 份）及设备解锁设置保持本机，修改先落本机后上传，离线与退出登录保留本机副本。远端变动且有待上传修改、或 NSFileVersion 有未解决冲突时选择整份账本，未选版本保存为「同步冲突时的另一版本」。切换时的不同版本同样先选择，并保留未选版本；切回本机复制当前账本。未清理可能仍被未到达冲突引用的附件文件。具体开关与布局见 [开发说明](../../../docs/DEVELOPMENT.md#可选-icloud-账本)。

已添加合成迁移、备份、版本选择和临时目录切换测试；当前没有 Swift 工具链，仅做语法、配置与生成工程静态核查，未执行 XCTest 或签名／iCloud 系统验证。Figma、历史原型、截图和分发包未同步，本票仍 in-progress。

| 事项 | 当前源码采用的口径与入口 |
|---|---|
| 资金观察与生活估算 | `Finance.swift`：默认观察未来 90 天；用截至昨天的 90 个完整自然日的九个 10 日窗口消费总额，中位数除以 10 估算每日生活费，包含零支出日；按 owner 2026-10-21 修复要求排除今天的支出及退款，避免当天补记改变预留。排除单笔大于 ¥500、已关联计划／房租的支出；关联退款抵原支出，未关联退款抵所在窗口，结果最低为 0。此方法不保证升级前后的保守可动用相同，需按组合清单核对。 |

| 最多五张与排序 | `ButlerCards.visible`：来信单独展示；其余同时最多五张，溢出排队。付款缺口优先级 0、到线 1、临近软线／无软线观察与回访 2、待明确流入 3、余额核对 4、导入「不像你」短评 5；无显式优先级的旧卡片使用回退排序。导入问题目前也走回退优先级 5，同级按新近程度和去重键排序。 |

| 冷启动 | `ProfileColdStart.swift`：最多三个问题、一次一题、允许跳过，最后汇成一份消费观修改提案，确认后生效；历史习惯不自动成为用户消费观。 |
| 心愿匹配与 30 天回访 | `Wishlist.swift`：仅将新增支出与考虑中的心愿匹配，日期在心愿创建日至其后 60 天、金额差不超过 10%，规范化标题包含或二字片段集合相似度至少 0.5。仅两边唯一匹配才自动关联，歧义由用户选择；关联后以实际购买日期加 30 天安排回访，记录值得／一般／有点后悔。60 天是匹配窗口，30 天是回访等待期。 |
| 反馈、静音与来信 | 同领域近 30 天两次后悔，或累计三次值得，可生成调整消费观的提案，仍待确认；收紧时次数减一／金额乘 80%。「以后别提」按主题持久静音。每周一 09:00 本地通知仅提示来信；每周来信含七日图表，历史余量使用当前设置回算，并非历史快照。 |

### 当前差异与未验证项
